Design language

Human operator guide. The dark theme already in use across the repo, extracted into a formal token system — color, surfaces, spacing, radii, type, and components — plus a component spec, a voice guide, a CSS generator, and a token linter that makes "uses only tokens" a checkable property. One source of truth so generated UIs are good and consistent by default.
Theme: dark · Targets: Claude Code · Codex · Cursor · Decision: extract the in-use theme, don't invent a palette.
About these two files. README.md is the AI-optimized source of truth; this README.html is the human view. The visual source of truth is design/tokens.json; design/tokens.css is generated from it. Convention: .md = AI optimization, .html = human view.

What it does — 5 functionalities

Each has its own doc under functionalities/ on a uniform schema.

01 Tokens (color · spacing · type)

The machine source of truth: tokens.json — color, severity P0–P3, surfaces, spacing, radii, type, component tokens.

02 Components

Anatomy + token map per component: score gauge, severity badge, finding card, table+chips, pill, lead, code.

03 Voice & tone

Microcopy guide: plain, honest, no overclaim — matching the project's rights-first tone.

04 CSS generation

tokens.json → tokens.css, deterministic. --check is a CI gate against stale CSS.

05 Token lint

Flags hardcoded hex/px not in the tokens, as file:line:col. Read-only. Exit 1 on violations.

How to run

node tasks/design-language/scripts/gen-css.mjs            # regenerate tokens.css
node tasks/design-language/scripts/gen-css.mjs --check    # CI gate: fail if stale
node tasks/design-language/scripts/lint-tokens.mjs <file> # flag hardcoded hex/px
node tasks/design-language/scripts/self-test.mjs          # offline, deterministic

In a UI: link/inline tokens.css, then use var(--…) everywhere — never a raw hex/px (the linter flags it). Follow components.md and voice.md.

Guarantees

  • Deterministic: same tokens.json → byte-identical tokens.css; lint output stably sorted.
  • Linter & --check are read-only; gen-css writes exactly one generated file.
  • Zero dependencies (Node ≥18).
  • Self-test proves tokens parse + carry core colors & P0–P3, generation is deterministic, and the linter flags/passes correctly.
